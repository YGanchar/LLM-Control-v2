# Развёртывание комплекса LLM-Control (сервер + клиент)

Эта инструкция описывает полное развёртывание системы LLM-Control: подготовку
сервера (`rtx`) и настройку клиента (управляющей машины с GUI).

Кратко: **клиент** управляет инстансами `llama-server` на **сервере** по SSH,
а **сервер** запускает LLM-модели и читает конфиги с общего NFS-диска.

---

## 1. Архитектура

```
┌─────────────── КЛИЕНТ (GUI) ───────────────┐
│  LLM-Control_v2  (PySide6, main_ui.py)     │
│  • сканер моделей                           │
│  • конфигуратор .mod / .conf                │
│  • управление по SSH (llmctl)               │
│  • мониторинг GPU/памяти по SSH             │
│                                             │
│  ~/.ssh/id_ed25519_llm  (SSH-ключ)          │
│  .env  (SSH_HOST, SERVER_USER, пути)        │
└───────────────┬─────────────────────────────┘
                │  SSH (ключ, беспарольно)
                │  sudo /usr/local/bin/llmctl <действие> [8081]
                ▼
┌─────────────── СЕРВЕР (rtx, 10.0.0.2) ────────────┐
│  systemd: llama-server.service        (режим 1, 8080, автостарт)
│  systemd: llama-server-8081.service   (режим 3, 8081, вручную)
│  /usr/local/bin/llmctl                (оболочка-менеджер)
│  /usr/local/bin/run-llama.sh          (запуск режима 1)
│  /usr/local/bin/run-llama-8081.sh     (запуск режима 3)
│  /usr/local/bin/llama-server          (бинарник llama.cpp)
│  /etc/sudoers.d/llmctl                (passwordless sudo для llmctl)
│                                             │
│  NFS: /srv/storage ≡ клиента /media/rtx-storage (конфиги)
│       /srv/models  ≡ клиента /media/rtx-models  (модели)
└─────────────────────────────────────────────────────┘
```

### Режимы работы (инстансы)

| Порт | Сервис                 | GPU           | Автостарт | Назначение            |
|------|------------------------|---------------|:-----------:|-----------------------|
| 8080 | `llama-server`         | GPU0 + GPU1   | да         | основной (режим 1)    |
| 8081 | `llama-server-8081`    | GPU1          | нет        | по требованию (режим 3) |

Инстансы выбираются суффиксом: `llmctl …` → 8080, `llmctl … 8081` → 8081.

## 2. Обязательные зависимости (до развёртывания)

Эти компоненты **не устанавливаются** скриптом `deploy-server.sh` — они
фундамент, на котором работает комплекс.

1. **NFS-монтирование.**
   - На сервере общие каталоги `/srv/storage` (конфиги) и `/srv/models` (модели).
   - На клиенте они смонтированы как `/media/rtx-storage` и `/media/rtx-models`.
   - Конфиги на сервере принадлежат пользователю `yuri` (редактируются с клиента
     без sudo); бинарники и сервисы — в каталогах root (нужен sudo).

2. **Бинарник `llama-server`** (сборка llama.cpp) на сервере, например
   `/usr/local/bin/llama-server`. Скрипт развёртывания проверит его наличие и
   предупредит, но не установит автоматически. Как собрать из исходников для одной
   или двух RTX — в [`Установка_llama-server.md`](Установка_llama-server.md).

3. **SSH-ключ** с клиента на сервер (см. п. 4).

4. **Пользователь** на сервере (по умолчанию `yuri`) с возможностью sudo.

> Если NFS и бинарник уже настроены (как на текущем сервере), можно сразу
> перейти к п. 4 — развёртыванию программного комплекса.

## 3. Развёртывание на сервере

### 3.1. Что ставит скрипт

`server/deploy-server.sh` устанавливает и настраивает:

- `/usr/local/bin/llmctl` — оболочка-менеджер инстансов
- `/usr/local/bin/run-llama.sh` — запуск режима 1 (8080, обе GPU)
- `/usr/local/bin/run-llama-8081.sh` — запуск режима 3 (8081, GPU1)
- `/etc/systemd/system/llama-server.service` — режим 1, **автостарт**
- `/etc/systemd/system/llama-server-8081.service` — режим 3, **без автостарта**
- `/etc/sudoers.d/llmctl` — `passwordless sudo` для `llmctl`

### 3.2. Установка (один раз)

Скопируйте всю директорию `server/` на сервер (например, в `/home/yuri/`), затем:

```bash
# На сервере:
cd /home/yuri/server
sudo ./deploy-server.sh
```

Скрипт:
- элевует привилегии через `sudo` (пароль запрашивается **один раз**);
- копирует файлы с правильными правами (`755` для скриптов, `644` для
  сервисов, `440` для sudoers);
- делает `systemctl daemon-reload`, включает `llama-server` в автостарт
  (`enable --now`), гарантирует, что `llama-server-8081` не в автостарте;
- создаёт `/etc/sudoers.d/llmctl` (идемпотентно — повторный запуск не дублирует
  строку);
- проверяет установку и выводит отчёт.

Скрипт безопасен для повторного запуска (идемпотентен).

#### Переменные скрипта (опционально)

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `PREFIX` | `/` | Корень, где монтировать. Для теста: `PREFIX=/tmp/llmtest` |
| `SUDO_USER_NAME` | `yuri` | Пользователь для строки sudoers |
| `LLAMA_SERVER_BIN` | `${PREFIX}usr/local/bin/llama-server` | Путь к бинарнику llama-server |
| `DRY_RUN` | `0` | Только показывать команды, не выполнять |

Пример — посмотреть, что сделает скрипт, без изменений системы:

```bash
sudo DRY_RUN=1 ./deploy-server.sh
```

### 3.3. Проверка после установки

```bash
# На сервере:
sudo /usr/local/bin/llmctl status          # статус режима 1
sudo /usr/local/bin/llmctl status 8081     # режим 2
sudo /usr/local/bin/llmctl mode            # вывести конфиг режима 1
systemctl is-enabled llama-server          # должен быть "enabled"
```

Если `llama-server` не установлен, сервисы не запустятся — сначала поставьте
бинарник (п. 2), затем повторите `sudo systemctl restart llama-server`.

## 4. Настройка SSH-доступа (клиент → сервер)

Приложение работает **только по SSH-ключам** (пароли не используются).

### Вариант A — встроенный мастер (рекомендуется)

При запуске, если беспарольный SSH не настроен, появится диалог:

- **Сгенерировать ключ** — создаст `~/.ssh/id_ed25519_llm` без пароля;
- **Скопировать ключ на сервер** — выполнит `ssh-copy-id` (потребует пароль
  один раз);
- **Показать инструкцию sudoers** — выведёт строку для `/etc/sudoers.d/llmctl`.

### Вариант B — вручную

```bash
# На клиенте — генерация ключа:
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_llm -N "" -C "llm-control-key"

# Копирование публичного ключа на сервер:
ssh-copy-id -i ~/.ssh/id_ed25519_llm.pub yuri@rtx

# Проверка беспарольного подключения:
ssh -i ~/.ssh/id_ed25519_llm yuri@rtx "echo OK"
```

### Настройка passwordless sudo на сервере

Для работы `llmctl` через `sudo` без ввода пароля, на сервере:

```bash
sudo visudo
# Добавить в конец:
yuri ALL=(ALL) NOPASSWD: /usr/local/bin/llmctl
```

Или одной командой:

```bash
echo 'yuri ALL=(ALL) NOPASSWD: /usr/local/bin/llmctl' | sudo tee /etc/sudoers.d/llmctl
chmod 440 /etc/sudoers.d/llmctl
```

> **Безопасность.** Строка даёт право запускать **только** `/usr/local/bin/llmctl`
> без пароля — не полный sudo. Файл sudoers имеет права `440` и владельца root.

## 5. Развёртывание на клиенте

### 5.1. Зависимости

```bash
pip install PySide6 python-dotenv psutil paramiko
```

### 5.2. Файл `.env`

Создайте `.env` в корне проекта:

```ini
# Пути
LAST_SCAN_PATH='/media/rtx-models'
LAST_MODS_PATH='/home/yuri/MODS'

# SSH-подключение к серверу
SSH_HOST="rtx"
SERVER_HOST="10.0.0.2"
SERVER_USER="yuri"
SERVER_MAC="44:8A:5B:5E:79:88"

# Пути конфигурации на сервере (NFS, видны клиенту)
DEFAULT_CONFIG_PATH="/media/rtx-storage/llama-mode.conf"
SECOND_CONFIG_PATH="/media/rtx-storage/llama-mode-8081.conf"

# Опционально
GPU_RAM_GB="12"
```

Ключевые параметры:

| Параметр | Описание |
|----------|----------|
| `SSH_HOST` | Имя/хост сервера (должен резолвиться из `.ssh/config` или `/etc/hosts`) |
| `SERVER_HOST` | IP для мониторинга и Wake-on-LAN |
| `SERVER_USER` | Пользователь на сервере |
| `SERVER_MAC` | MAC интерфейса сервера для WoL |
| `DEFAULT_CONFIG_PATH` | Путь к `.conf` инстанса 8080 |
| `SECOND_CONFIG_PATH` | Путь к `.conf` инстанса 8081 |

> **Важно.** `.env` содержит учётные данные (SSH-пути). Не коммитьте его в Git —
> он уже исключён из архивов и сборки.

### 5.3. Запуск

```bash
# Из исходного кода:
python main.py

# Собранный бинарник (PyInstaller):
cd dist
./LLM-Control_v2
```

### 5.4. Сборка бинарника

```bash
pyinstaller --onefile --noconsole --name LLM-Control_v2 main.py
```

Собранный файл лежит в `dist/LLM-Control_v2`; рядом с ним должен лежать `.env`
(замороженная сборка читает `.env` рядом с исполняемым).

## 6. Управление инстансами (справочник `llmctl`)

На сервере:

```bash
sudo /usr/local/bin/llmctl start        # запустить инстанс 8080
sudo /usr/local/bin/llmctl start 8081   # инстанс 8081
sudo /usr/local/bin/llmctl stop         # остановить (форсированно освободит порт)
sudo /usr/local/bin/llmctl restart      # перезапустить
sudo /usr/local/bin/llmctl status       # статус systemd-сервиса
sudo /usr/local/bin/llmctl mode         # вывести текущий конфиг
sudo /usr/local/bin/llmctl logs         # логи journald (tail -f)
```

Клиент вызывает то же самое через SSH:

```bash
ssh yuri@rtx "sudo /usr/local/bin/llmctl status"
```

## 7. Типичные проблемы

| Симptom | Причина / решение |
|---------|-------------------|
| `Permission denied (publickey)` | Ключ не скопирован; повторите `ssh-copy-id` |
| `llmctl: Command not found` / запрос пароля sudo | Не настроен `/etc/sudoers.d/llmctl` |
| `Unit llama-server.service not found` | Скрит `deploy-server.sh` не отработал или `daemon-reload` не сделан |
| Инстанс не стартует после перезагрузки | Проверьте `systemctl is-enabled llama-server` (должно быть `enabled`) |
| `llama-server: No such file` | Бинарник не установлен в `/usr/local/bin/llama-server` |
| Конфиг не применяется | Конфиг на NFS должен быть в кавычках: `EXTRA="--flash-attn"` (см. `ИНСТРУКЦИЯ.md`) |
| WoL не включает сервер | Проверьте MAC в `.env` и включён ли WoL в BIOS |

## 8. Что не входит в развёртывание

- **NFS-монтирование** — настраивается отдельно (зависит от инфраструктуры).
- **Установка `llama-server`** — бинарник llama.cpp ставится независимо. Как
  собрать его из исходников для одной или двух RTX —
  в [`Установка_llama-server.md`](Установка_llama-server.md).
- **Расположение моделей** — `.gguf` файлы размещаются в `/srv/models/…`.

См. также: [`ИНСТРУКЦИЯ.md`](../ИНСТРУКЦИЯ.md) — руководство пользователя,
[`MODES.md`](../MODES.md) — спецификация архитектуры и режимов,
[`Установка_llama-server.md`](Установка_llama-server.md) — сборка бинарника.
