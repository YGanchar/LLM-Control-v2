# LLM-Control v2 — Инструкция по применению

## Обзор приложения

**LLM-Control v2** — это десктопное приложение на Python/PySide6 для управления локальным сервером с GPU (RTX) и запуска локальных LLM-моделей через `llama-server`.

### Основные возможности

1. **Сканер моделей** — поиск `.gguf` файлов на диске, отображение их в таблице с информацией о размере и наличии vision-модуля
2. **Конфигуратор** — создание и редактирование `.mod` файлов (конфигурация запуска llama-server) с автоматическим подбором параметров
3. **Управление сервером** — удалённое управление инстансами llama-server через SSH, Wake-on-LAN, мониторинг ресурсов в реальном времени

## Требования

### Системные требования
- **ОС:** Linux (Ubuntu 20.04+)
- **Python:** 3.8+ (для разработки)
- **GPU:** NVIDIA RTX (с драйверами и CUDA)
- **Сеть:** Соединение с сервером RTX по SSH

### Зависимости

```bash
pip install PySide6 python-dotenv psutil paramiko
```

### Настройка сервера (удалённый RTX-сервер)

### Обязательные требования

1. Установить `llama-server` и `llmctl` на сервере
2. Настроить SSH-ключи для безпарольного доступа
3. Обеспечить Wake-on-LAN на сетевой карте сервера

### Настройка SSH-ключей (обязательно)

Приложение использует **только SSH-ключи** для аутентификации. Пароли больше не поддерживаются.

**Шаг 1: Генерация SSH-ключа (если нет)**

```bash
# На клиенте (локальная машина):
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_llm -N "" -C "llm-control-key"
```

**Шаг 2: Копирование ключа на сервер**

```bash
# Скопировать публичный ключ на сервер:
ssh-copy-id -i ~/.ssh/id_ed25519_llm.pub yuri@rtx

# Или вручную:
cat ~/.ssh/id_ed25519_llm.pub | ssh yuri@rtx "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

# Проверка:
ssh -i ~/.ssh/id_ed25519_llm yuri@rtx "echo OK"
```

**Шаг 3: Настройка sudoers на сервере (для беспарольного sudo)**

```bash
# На сервере RTX:
sudo visudo

# Добавьте строку (замените 'yuri' на вашего пользователя):
yuri ALL=(ALL) NOPASSWD: /usr/local/bin/llmctl
```

Или используйте команду:

```bash
# На сервере:
echo 'yuri ALL=(ALL) NOPASSWD: /usr/local/bin/llmctl' | sudo tee -a /etc/sudoers.d/llmctl
```

### Встроенный мастер настройки SSH

Приложение имеет встроенный мастер настройки SSH-доступа. Если ключи не найдены или подключение не работает, при запуске появится диалог с предложениями:

- **Сгенерировать ключ** — создаст новый SSH-ключ без пароля
- **Скопировать ключ на сервер** — выполнит `ssh-copy-id`
- **Показать инструкцию** — выведет подробные шаги настройки

## Конфигурация (.env)

Создайте файл `.env` в корне проекта:

```ini
# Пути
LAST_SCAN_PATH='/media/rtx-models'
LAST_MODS_PATH='/home/yuri/MODS/new'

# SSH-подключение к серверу
SSH_HOST="rtx-auto"
SERVER_HOST="10.0.0.2"
SERVER_USER="yuri"
SERVER_MAC="44:8A:5B:5E:79:88"

# Пути конфигурации на сервере
DEFAULT_CONFIG_PATH="/media/rtx-storage/llama-mode.conf"
SECOND_CONFIG_PATH="/media/rtx-storage/llama-mode-8081.conf"

# Опционально
GPU_RAM_GB="12"
```

### Важные параметры

| Параметр | Описание |
|----------|----------|
| `SSH_HOST` | Имя хоста или IP сервера (должен резолвиться из `.ssh/config` или `/etc/hosts`) |
| `SERVER_HOST` | IP-адрес сервера для мониторинга и WoL |
| `SERVER_USER` | Имя пользователя на сервере |
| `SERVER_MAC` | MAC-адрес сетевого интерфейса сервера для Wake-on-LAN |
| `DEFAULT_CONFIG_PATH` | Путь к `.conf` файлу для инстанса на порту 8080 |
| `SECOND_CONFIG_PATH` | Путь к `.conf` файлу для инстанса на порту 8081 |

> **Примечание:** Параметр `SERVER_PASS` больше не используется. Аутентификация осуществляется только по SSH-ключам.

## Пошаговое использование

### 1. Сканирование моделей

1. Откройте вкладку **"Сканер Моделей"**
2. Нажмите **"Обзор..."** и выберите директорию с `.gguf` файлами (например, `/media/rtx-models`)
3. Нажмите **"Сканировать"**
4. Дождитесь завершения сканирования
5. Найдите нужную модель в таблице (сортировка по клику на заголовки колонок)
6. **Двойной клик** по строке выберет модель и переключит на вкладку **"Параметры модели"**

### 2. Конфигурация модели

На вкладке **"Параметры модели"**:

1. **Выберите каталог с .mod файлами** (кнопка "Обзор" в правом верхнем углу)
2. Введите или выберите имя модели
3. Просмотрите сгенерированную конфигурацию в правом текстовом поле
4. Отредактируйте параметры при необходимости:
   - `MODEL` — путь к модели на сервере
   - `PORT` — порт (8080 или 8081)
   - `CTX` — размер контекста
   - `NGL` — количество слоев, загруженных в GPU
   - `BATCH` — размер батча
   - `THREADS` — количество потоков CPU
   - `EXTRA` — дополнительные аргументы
5. Нажмите **"Сохранить"** для записи в `.mod` файл
6. Нажмите **"Сервер"** для перехода к управлению сервером с этой конфигурацией

#### Автоматический подбор параметров

Приложение автоматически подбирает параметры на основе:
- Размера модели (ГБ)
- Квантизации (Q8_0, Q6_K, Q4_K_M и т.д.)
- Объёма VRAM вашей GPU (параметр `GPU_RAM_GB` в `.env`)

### 3. Управление сервером

На вкладке **"Сервер RTX"**:

#### Переключение инстансов

Используйте радио-кнопки вверху для выбора управляемого инстанса:
- **Модель 1 (порт 8080, автостарт)** — основной инстанс
- **Модель 2 (порт 8081, вручную, GPU1)** — дополнительный инстанс

#### Основные операции

| Кнопка | Действие |
|--------|----------|
| **Применить** | Сохранить конфигурацию из текстового поля в `.conf` файл на сервере |
| **Старт** | Запустить llama-server с текущей конфигурацией |
| **Стоп** | Остановить текущий инстанс |
| **Перезапуск** | Перезапустить текущий инстанс |
| **Статус** | Показать статус текущего инстанса |
| **Конфиг** | Показать текущую конфигурацию сервера |
| **Логи** | Показать логи сервера в реальном времени |

#### Управление питанием

| Кнопка | Действие |
|--------|----------|
| **Включить (WoL)** | Отправить Magic Packet для включения сервера |
| **Выключить (SSH)** | Корректно выключить сервер через SSH |

#### Валидация конфигурации

Перед сохранением приложение проверяет:
- Наличие обязательных параметров: `MODEL`, `PORT`, `CTX`, `NGL`
- Корректность диапазона порта (1-65535)
- Минимальный размер контекста (≥8)
- Корректность `NGL` (>0 или "auto")
- Конфликт `NGL="auto"` с ручным `--tensor-split` (вызывает OOM)
- Отсутствие слипания строк в многострочных значениях (пробел перед `\`)

## Мониторинг ресурсов

В нижней части главного окна отображается панель статуса:

| Индикатор | Описание |
|-----------|----------|
| **SRV CPU** | Загрузка CPU сервера (%) |
| **SRV RAM** | Использование RAM сервера (%) |
| **8080** | Статус инстанса на порту 8080 (ACTIVE/OFFLINE + VRAM) |
| **8081** | Статус инстанса на порту 8081 (ACTIVE/OFFLINE + VRAM) |
| **GPU0/1** | Использование VRAM и потребление энергии каждой GPU |

Данные обновляются каждые 2 секунды.

## Формат .mod файла

`.mod` файл — это конфигурация для запуска llama-server:

```ini
MODEL="/srv/models/NVIDIA-Nemotron-3-Nano-4B-Q8_0/NVIDIA-Nemotron-3-Nano-4B-Q8_0.gguf"
HOST="0.0.0.0"
PORT="8080"

THREADS="4"

CTX="32768"
BATCH="320"
NGL="60"

EXTRA="--flash-attn"
```

### Обязательные параметры

- `MODEL` — полный путь к `.gguf` файлу на сервере
- `PORT` — порт для подключения (обычно 8080 или 8081)
- `CTX` — размер контекстного окна
- `NGL` — количество слоев в GPU (или "auto" для автоматического подбора)

### Опциональные параметры

- `HOST` — адрес привязки (по умолчанию `0.0.0.0`)
- `THREADS` — количество потоков CPU (по умолчанию 4)
- `BATCH` — размер батча (по умолчанию 320)
- `EXTRA` — дополнительные аргументы командной строки

## Распределение моделей по серверу

Приложение преобразует клиентские пути в серверные:

```
Клиент: /media/rtx-models/NVIDIA-Nemotron-3-Nano-4B-Q8_0/model.gguf
         ↓
Сервер: /srv/models/NVIDIA-Nemotron-3-Nano-4B-Q8_0/model.gguf
```

Каждая модель размещается в отдельной поддиректории на сервере.

## Устранение неполадок

### SSH-подключение не устанавливается

1. Проверьте, что `SSH_HOST` резолвится корректно
2. Убедитесь, что SSH-ключ настроен и работает:
   ```bash
   ssh -i ~/.ssh/id_ed25519_llm yuri@rtx "echo OK"
   ```
3. Проверьте, что сервер включен (попробуйте WoL)
4. Проверьте логи в текстовом поле сервера

### WoL не работает

1. Убедитесь, что MAC-адрес в `.env` совпадает с адресом сервера
2. Проверьте, что Wake-on-LAN включен в BIOS/UEFI сервера
3. Проверьте, что сетевая карта сервера поддерживает WoL
4. Убедитесь, что роутер транслирует broadcast-пакеты

### Ошибка "SSH-ключ не найден"

Приложение ищет ключи в следующем порядке:
1. `~/.ssh/id_ed25519_llm` (специальный ключ для LLM-Control)
2. `~/.ssh/id_ed25519` (стандартный Ed25519)
3. `~/.ssh/id_rsa` (стандартный RSA)

Если ни один ключ не найден:
- Используйте встроенный мастер настройки (появится при запуске)
- Или сгенерируйте ключ вручную:
  ```bash
  ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_llm -N "" -C "llm-control-key"
  ssh-copy-id -i ~/.ssh/id_ed25519_llm.pub yuri@rtx
  ```

### Ошибка валидации конфигурации

Приложение покажет список проблем. Основные:
- **Отсутствуют обязательные параметры** — добавьте `MODEL`, `PORT`, `CTX`, `NGL`
- **PORT: невалидный диапазон** — используйте порт от 1 до 65535
- **CTX: слишком маленький** — минимум 8
- **NGL="auto" вместе с --tensor-split** — уберите `--tensor-split` или задайте NGL числом

### Мониторинг показывает "OFFLINE"

1. Проверьте, что сервер включен
2. Проверьте, что порт 22 (SSH) открыт
3. Проверьте, что `SERVER_HOST` в `.env` корректен

### Приложение не запускается

1. Убедитесь, что все зависимости установлены:
   ```bash
   pip install PySide6 python-dotenv psutil paramiko
   ```
2. Проверьте, что `.env` файл существует в корне проекта

Все действия логируются в консоль и файл (если настроено). Формат:

```
2026-08-10 12:34:56,789 - INFO - [MAIN] Запуск приложения. Директория: /home/yuri/projects/LLM-Cluster/LLM-Control-v2
```

- **CRITICAL** — критические ошибки, после которых приложение завершается

## Безопасность

### Аутентификация

Приложение использует **только SSH-ключи** для аутентификации. Пароли больше не поддерживаются.

**Рекомендации:**
- Храните приватный ключ в безопасном месте
- Не коммитьте SSH-ключи в Git
- Используйте ограниченные привилегии для пользователя
- Настройте `sudoers` для `llmctl` (убирает необходимость полного sudo)

### SSH-ключи

Приложение ищет SSH-ключи в следующем порядке:
1. `~/.ssh/id_ed25519_llm` (специальный ключ для LLM-Control)
2. `~/.ssh/id_ed25519` (стандартный Ed25519)
3. `~/.ssh/id_rsa` (стандартный RSA)

Рекомендуется использовать Ed25519 ключ без пароля (passphrase) для автоматической работы.
